# 기획

바탕화면을 돌아다니고, 마우스에 붙어 다니며, 마우스에 반응하는 데스크탑 펫. **Windows 우선**, GitHub README의 다운로드 버튼으로 배포한다.

## 확정 사항

- 플랫폼: Windows 10/11 x64 먼저
- 배포: GitHub Releases (설치 파일 + 포터블 zip), README에서 고정 링크로 다운로드
- 스택: Electron + TypeScript (엔진과 셸을 분리해서 나중에 Tauri로 옮길 수 있게 둠)
- 에셋: 앱은 **스킨 폴더**를 읽는다. 직접 만든 기본 마스코트(Sprout)가 폴백으로 항상 들어 있고, 저장소 소유자가 개인·지인용으로 제공한 ちいかわ 이미지로 만든 `skins/usagi`(우사기), `skins/hachiware`(하치와레), `skins/chiikawa`(치이카와), `skins/rakko`(랏코)를 함께 담는다. 새 캐릭터는 앱 안의 **스킨 메이커**(배경 지우기·포즈 지정·크기/방향 맞춤·저장)로 만든다.
- 에셋 권리: 이 캐릭터 이미지들의 저작권은 권리자(© ナガノ)에게 있고 저장소 라이선스 대상이 아니다. 요청이 오면 해당 `skins/<이름>` 폴더를 지우고 `electron-builder.yml`의 extraResources 항목, `.gitignore`의 예외 줄, (usagi라면) `DEFAULT_SETTINGS.skin`(기본 스킨)을 되돌리면 된다. 스킨이 없으면 앱은 Sprout으로 시작한다.

## 구조

- **오버레이**: 모니터마다 그 모니터의 작업 영역 크기인 투명·프레임 없음·항상 위 창을 한 장씩 둔다(모니터마다 배율이 달라도 창 안은 같은 DIP 좌표). 창은 움직이지 않고 Canvas로 그리기만 한다. 모니터가 바뀌면(꽂기·뽑기·해상도·작업 표시줄) 창을 새로 만들거나 닫거나 다시 맞춘다. 새 창을 먼저 만든 뒤 낡은 창을 닫아서 펫이 설 곳이 늘 있다.
- **시뮬레이션은 메인 프로세스 한 곳**(`src/shell/stage.ts`): 펫 하나가 모든 모니터가 공유하는 좌표(주 모니터 모서리가 0,0)에서 움직인다. 창에는 매 틱 `ViewFrame`(펫 모습 + 속도)을 보내고, 창은 도착한 시각부터 속도만큼 밀어서 그려서 메시지 간격이 들쭉날쭉해도 부드럽다(`src/renderer/remote.ts`). 브라우저 테스트 페이지는 메인이 없어서 페이지가 엔진을 직접 돌린다.
- **클릭 통과**: 기본은 클릭 통과. 메인 프로세스가 커서를 폴링해서 펫 히트박스(타원) 위에 있을 때만, 그 점이 속한 창 하나만 마우스를 받는다. 마우스가 눌린 창은 드래그가 끝날 때까지 받는다(펫이 모니터를 넘어가도). 창은 버튼 누름·뗌만 알리고, 호버·쓰다듬기·드래그는 폴링한 커서로 처리한다. 붙어있기 모드와 "방해하지 않기"는 항상 통과.
- **엔진**(`src/engine`): 모드(auto/follow/attach/wander), 상태(idle/walk/run/sit/sleep/held/fall/land/surprised/happy), 상호작용(호버·클릭·쓰다듬기·드래그·던지기·도망·수면). 시간과 난수를 주입해서 결정적으로 테스트한다.
- **대사**(`src/engine/speech.ts`): 스킨 manifest의 `lines`(상황별 줄)를 엔진이 고른다. 상황(클릭·쓰다듬기·들어 올림·던짐·착지·도망·따라감·붙음·앉음·잠·깸·모니터 건너기·혼잣말·인사, 그리고 부름·돌아옴·충전기·배터리 부족)마다 확률과 쿨다운이 있고, 같은 줄을 연달아 말하지 않고, 대사가 없으면 난수도 쓰지 않아서 동작이 그대로다. 글자는 말풍선 없이 하트·z와 같은 입자로 그린다: 짧은 소리(`float`)는 위로 떠오르며 사라지고 문장(`hold`)은 머리 위에 따라다니며 잠깐 떠 있다 사라진다. 시뮬레이션이 메인에 있으니 고르는 것도 메인이고, 스킨의 줄은 렌더러가 스킨을 읽어 `SkinReport`로 알려 준다. 설정 `speech`는 all(반응+혼잣말) / reactions / off.
- **숨기기·부르기**(`Stage.setHidden/call`, `Pet.call`): 숨기면 시뮬레이션을 멈추고 모든 창을 비우고 마우스를 통과시킨다(창은 그대로 두어서 모니터 변경 처리와 부딪치지 않는다). 숨김은 저장하지 않는다(다시 켜면 보인다). 부르면 숨어 있어도 나오고, 가까우면 커서 옆까지 달려오고(`CALL_FAR`), 멀거나 다른 모니터면 커서 위에서 떨어진다. 6초 안에 못 닿으면 떨어져 내리고, 또 6초가 지나면 포기하고 그 자리에서 대답한다. 전역 단축키는 `Ctrl+Alt+Shift` + `B`(종료) `H`(숨기기) `C`(부르기)다.
- **컴퓨터 소식**(`Pet.notice`, `src/shared/power.ts`): 잠금 해제·절전 복귀(`powerMonitor`, 잠금 중의 복귀는 잠금 해제가 대신 맞는다)·충전기 꽂기/빼기(`on-ac`/`on-battery`)·배터리 부족(오버레이가 `navigator.getBattery()`로 읽어 IPC로 알리고, `BatteryWatch`가 20% 아래로 처음 떨어질 때만 알린다)에 펫이 깨어나 반응하고 한마디 한다. 숨은 동안의 소식은 버린다.
- **바뀐 점 알림**(`CHANGELOG.md`, `src/shared/changelog.ts`, `src/shell/whats-new.ts`): 사용자가 알아챌 변경을 버전마다 한 줄씩 적는다. 앱은 `userData/state.json`에 마지막으로 실행한 버전을 적어 두고, 달라졌으면 그 사이 버전들의 요약을 알림으로 보여 준다(처음 설치한 PC는 조용히 기록만 한다. 이 기능 이전부터 쓰던 PC는 `userData/skins` 폴더가 이미 있는 것으로 알아본다). 워크플로는 같은 파일의 그 버전 항목을 릴리스 설명으로 쓰고, 항목이 없으면 릴리스를 멈춘다. `package.json` 버전의 항목이 있는지는 단위 테스트가 지킨다.
- **여러 모니터의 지형**(`src/engine/region.ts`): 모니터마다 작업 영역 사각형 하나, 그 합집합이 펫이 설 수 있는 곳이다. 몸(히트박스) 전체가 합집합 안에 있어야 하고 두 모니터에 걸치는 건 된다. 바닥은 모니터마다 다르고(걸쳐 있으면 더 높은 쪽), 바닥을 걷다 높이가 다른 바닥을 만나면 같은 x에서 계단처럼 오르내린다. 모니터가 하나면 예전과 똑같이 동작한다.
- **스킨**: 폴더 + `manifest.json`. 포즈는 정지 이미지, GIF/APNG/WebP, 스프라이트 시트 어느 것이든 되고, 정지 이미지의 움직임은 엔진이 찌그러짐·통통 튐으로 만든다. 그림 자체가 움직이는 포즈는 `motion: off`로 엔진 움직임을 끈다. `states`로 상황별 포즈를 바꿀 수 있다.
- **스킨 메이커**(`src/maker`, `src/renderer/maker.*`): 별도 창(`buddy://app/maker.html`)에서 이미지를 불러와 배경을 지우고(테두리 색 감지 + 바깥쪽 채우기 + 가장자리 보정), 같은 그림의 크기를 맞추고, 한 캔버스에 발 위치를 맞춰 정렬한 뒤 스킨 폴더로 저장한다. 저장은 메인 프로세스가 요청을 검증(폴더 이름, 파일 이름, PNG 시그니처, manifest)하고 임시 폴더를 거쳐 교체한다. 메이커 창만 저장 IPC를 쓸 수 있고 오버레이 창에는 없다.
- **정지 그림 움직임**(`src/maker/animate.ts`): 그림에서 귀(머리 위의 좁은 띠), 눈(속이 찬 어두운 덩어리), 꼬리(몸에 비해 작은 흰 덩어리)를 찾고, 귀는 줄 단위로 기울이고 꼬리는 걸린 곳을 축으로 돌리고 눈은 지운 뒤 납작하게 다시 그려서 프레임을 만든다. 쉬는 프레임은 원본 픽셀 그대로고, 오래 머무는 프레임은 긴 duration 하나로 처리해서 시트가 작다. 걷기·달리기는 엔진의 걸음 주기(0.5초, 0.29초)에 맞춰 만들고, 엔진은 걷기·달리기에 들어갈 때 주기를 처음부터 시작해서 시트와 홉이 어긋나지 않는다.

## Windows 실기기 확인 목록 (M1)

개발 환경이 Linux라서 아래 항목은 Windows에서 직접 확인해야 한다.

1. 펫이 투명한 배경 위에 그려지고 (검은 배경이 아님) 작업 표시줄 위에 선다
2. 펫이 아닌 곳을 클릭하면 아래 창이 정상 동작한다 (클릭 통과)
3. 펫을 클릭·드래그할 수 있고, 빠르게 끌어도 놓치지 않는다
4. 배율 125% / 150% 에서도 펫 위치와 클릭 위치가 맞는다
5. 붙어있기 모드에서 평소처럼 작업할 수 있다
6. 트레이 메뉴가 열리고, 종료와 `Ctrl+Alt+Shift+B`가 동작한다
7. 전체화면 영상/게임 위에서의 동작
8. 설치 → 실행 → 제거, 자동 시작
9. 모니터 두 대: 펫이 경계를 넘어 다니고, 경계에 걸쳐서도 양쪽에 그려지고, 한 모니터가 낮을 때(작업 표시줄, 해상도) 계단처럼 오르내린다
10. 배율이 서로 다른 모니터(예: 100%와 150%) 사이에서 창 위치·크기와 클릭 위치가 맞는다. 안 맞으면 로그에 `overlay of display … is at … instead of …`가 남는다
11. 모니터를 뽑고 꽂고, 해상도를 바꾸고, 주 모니터를 바꿔도 펫이 사라지지 않는다
12. 트레이 > 모니터: 모든 모니터 / 주 모니터만 / 모니터 하나. 고른 모니터를 뽑으면 주 모니터로 돌아오고, 다시 꽂으면 그 모니터로 간다
13. 한 모니터에서 잡은 펫을 다른 모니터까지 끌고 가서 놓아도 놓치지 않는다
14. 트레이 → **스킨 만들기…** 로 메이커 창이 열리고, 이미지를 끌어다 놓거나 파일 선택으로 불러와 저장하면 `%APPDATA%\desktop-buddy\skins`에 생기며, **지금 이 스킨 쓰기**가 바로 반영된다. 메이커 창 위에서는 펫이 클릭을 가로채지 않는다
15. 작업 관리자에서 CPU/GPU 사용량: 가만히 있을 때(잠자기/앉기)는 거의 0, 걸을 때도 낮아야 한다. 작업 영역 크기의 투명 창은 Windows에서 비용이 클 수 있어서, 높으면 창을 펫 크기로 줄이는 방식을 검토한다
16. 대사: 한글이 맑은 고딕으로 또렷하게 그려지고, 화면 가장자리에서 글자가 잘리지 않는다. 트레이 > 대사의 모두 / 반응만 / 끄기가 동작한다
17. 캐릭터 5종(Usagi, Hachiware, Chiikawa, Rakko, Sprout)을 번갈아 골라 보면 크기가 크게 차이 나지 않고, 포즈가 바뀔 때 발이 바닥선에서 뜨지 않는다
18. 자동 업데이트: 설치 파일로 설치한 앱의 트레이에 **업데이트 자동 확인**과 **업데이트 확인**이 보인다(포터블 zip에는 **새 버전 확인 (GitHub 열기)** 하나만 보여야 한다). 0.3.1을 설치한 뒤 다음 버전을 릴리스하면 알림이 뜨고, 메뉴가 **설치하고 다시 시작**으로 바뀌고, 그것을 누르면 앱이 새 버전으로 다시 뜬다. 안 되면 `%APPDATA%\desktop-buddy\buddy.log`의 `updates:` 줄(설치형으로 판별했는지)과 `[updater]` 줄(받기·검증 단계)을 본다
19. 전역 단축키: 다른 프로그램(메모장, 브라우저)을 쓰는 중에 `Ctrl+Alt+Shift+H`로 숨기고 다시 불러내고, `Ctrl+Alt+Shift+C`로 부르면 펫이 마우스 옆으로 온다. 트레이의 **펫 부르기**·**잠깐 숨기기**도 같다. 이미 다른 프로그램이 쓰는 조합이면 로그에 `could not register`가 남는다
20. 컴퓨터 소식: `Win+L`로 잠그고 풀면 펫이 반긴다. 절전에서 깨어나면(잠금 화면이 없는 PC에서도) 반긴다. 노트북에서 충전기를 꽂고 뺄 때 한마디 하고, 배터리가 20% 아래로 떨어지면 한 번 알린다. 데스크탑 PC는 배터리 소식이 없는 게 정상이다
21. 바뀐 점 알림: 0.3.1 설치형이 0.3.2를 받아 설치한 뒤 처음 켜질 때 "v0.3.2 업데이트 완료"와 바뀐 점 몇 줄이 알림으로 뜨고(글자가 잘리지 않는지), 알림을 누르면 릴리스 페이지가 열린다. 같은 버전으로 다시 켜면 또 뜨지 않는다. 트레이 **바뀐 점 보기**도 같은 페이지를 연다
22. 한국어 Windows에서 트레이 > 캐릭터(스킨)의 이름이 랏코, 스프라우트, 우사기, 치이카와, 하치와레 순서로 한글로 보인다
